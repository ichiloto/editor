# Ichiloto Editor 0.5.0

Released: 2026-08-21

`0.5.0` delivers the first complete terminal authoring workspace for Ichiloto Engine 0.5 projects.

Maps, NPCs, event commands, database records, cinematics, summons, validation, and playtesting now meet in one editor. The Editor modifies the PHP-authored project files that the Engine runs while preserving surrounding source, stable identities, and content that was not changed through the interface.

## Highlights

### Map and NPC authoring

Maps can be created, painted, resized, duplicated, and removed from the terminal workspace. Brush, line, rectangle, and fill tools work alongside an event layer, character map, background music, weighted encounters, transfers, collision geometry, and map metadata.

Map-local NPCs have dedicated authoring for placement, sprites, directional sprites, fixed or bounded wandering, visibility conditions, dialogue variants, inline scripts, and completion writes. Reference pickers use the maps, events, and records that the project actually contains.

### Schema-driven project databases

The Database workspace authors actors, classes, skills, quests, animations, states, troops, skits, common events, terms, system settings, knowledge records, and project policy through reusable schemas.

Records keep durable identities as labels and presentation fields change. Shared backing files are coordinated so saving one category does not overwrite edits made through another view of the same source.

Animation frame sounds are selected from the project's SFX catalogue, and summon effect timing cues are selected from the current timeline. Both store stable authored values and provide an explicit way to clear an optional selection.

### A first-class Cutscenes workspace

Cinematic and summon assets can be discovered, created, edited, previewed, and deleted as paired definitions. The workspace provides cast management, nested command trees, parallel lanes, camera routes, skip policies, finalizers, summon tracks, keyframes, cues, and actor assignments.

Preview runs through Engine 0.5's cinematic and summon playback sessions. The authoring preview and the shipped game therefore agree on command timing, camera behavior, skip results, and final state.

### Source-preserving edits

The Editor changes the smallest supported span of a PHP-authored data file instead of regenerating the whole file. Surrounding code, formatting, comments, array keys, constructor calls, escape sequences, and unrelated records remain intact.

Paired-file saves are atomic, no-op saves leave the source untouched, and every editing operation participates in undo and redo. Dirty state is based on content, so undoing back to the saved state makes the project clean again.

Opt-in pre-save backups reserve unique destinations, preserving each recovery point even when the same file is saved repeatedly within one second.

### Project-wide validation

One `ProjectValidator` checks the contracts shared by the Editor and Console. It covers record identities, references, maps, NPCs, events, cinematics, summons, achievements, battle escape policy, equipment optimization, and save compatibility.

Diagnostics point back to the authored file or record and explain why the runtime would reject it. Contested identifiers fail closed rather than selecting an arbitrary claimant.

### Isolated playtesting

Playtests launch the real game against a disposable project overlay. Unsaved map and cutscene work can be exercised from the cursor without writing playtest state into the project being edited.

## Upgrade Notes

Editor 0.5 requires PHP 8.4, Symfony Console 8, and Ichiloto Engine 0.5.

Install or update the package with Composer:

```bash
composer require ichiloto/editor:^0.5 --with-all-dependencies
```

Most users open the Editor through Console 0.5:

```bash
composer global require ichiloto/console:^0.5 --with-all-dependencies
ichiloto edit
```

The optional production-project verification tests use `ICHILOTO_GAME_SRC` when a real game fixture should participate in the gate. They skip cleanly when no external project has been selected.

The development suite now uses Pest 5.1 and PHPUnit 13-compatible tooling.
