# Ichiloto Editor 0.5.1

`0.5.1` restores compatibility with PHP 8.4 and strengthens the safety of editing
PHP-authored projects. It also adds authoring tools for battle-entry rules and
conditional map music, with clearer database layouts and consistent list navigation.

## Highlights

### PHP 8.4 compatibility restored

The Editor no longer uses the PHP 8.5 pipe operator in its layout calculation.
This fixes a parse error in `0.5.0` when the Editor is loaded on PHP 8.4, including
through Ichiloto Console. The declared minimum remains PHP 8.4.1.

### Safer map saves and lifecycle operations

Map metadata edits now preserve surrounding authored PHP instead of regenerating
the data file. Comments, imports, expressions, unknown fields, and unchanged map
members are retained; edits that cannot preserve the source are refused with a
specific diagnostic rather than flattened into replacement data.

Saving, creating, duplicating, moving, and deleting maps use the shared file-set
transaction boundary. Validation checks staged content in its intended runtime
context, and failed operations attempt to restore affected filesystem state,
reporting any paths that could not be restored. Backups cover
changed members, no-op saves leave files untouched, and deleting a map preserves
unrelated files in its folder.

Validation of authored PHP is isolated from the running editor. The release also
fixes stale validation results, exact-path checks for moved maps, and rollback of
file contents, permissions, modification times, and newly created directories.

### Battle-entry rule authoring

The Database gains a Battle Entry category for
`assets/Data/battle-entry-rules.php`. Authors can select durable actor references,
edit roster predicates and conditions, assign temporary stat-stage effects, and
configure reversible world writes. Rules expose their execution order, and troops
can be classified as ordinary encounters or bosses.

Validation reports malformed rules, duplicate identities, unsupported effects,
and invalid references. The Editor authors and validates the data; the Engine
remains responsible for evaluating and executing it.

### Conditional map music

The map Inspector now edits ordered `bgmVariants` alongside the default background
track. Track pickers, condition editing, reordering, removal, undo, and reload
preserve authored order and unowned fields. Diagnostics identify missing tracks,
unsupported shapes, and unconditional variants that make later entries unreachable.

### More consistent navigation and layouts

Selection lists wrap at their first and last entries without wrapping map cursors
or text-editing positions. Database notes and animation-frame lists make better
use of available width. Record reordering is offered only when the backing format
can save that order, rather than appearing to work and being lost on reload.

## Upgrade Notes

The package requirements remain PHP 8.4.1 or newer within PHP 8, `ext-mbstring`,
Symfony Console 8, and Ichiloto Engine 0.5.

For projects that depend directly on the Editor:

```bash
composer require ichiloto/editor:^0.5.1 --with-all-dependencies
```

For an existing global Ichiloto Console installation:

```bash
composer global update ichiloto/editor --with-all-dependencies
ichiloto edit
```

**Engine compatibility:** published Engine 0.5.0 does not execute battle-entry
rules or resolve `bgmVariants`. The Editor can author this data, but those features
will not affect gameplay until the game uses an Engine release that supports
them. Installing Editor 0.5.1 alone does not add these runtime capabilities.

## Validation

The repository's CI checks Composer metadata, platform requirements, PHP 8.4 source
syntax, PHPStan, dependency advisories, and the Pest suite. Its test matrix covers
Ubuntu with PHP 8.4 and 8.5, and macOS with PHP 8.4.

Regression coverage includes source-preserving map edits, transactional lifecycle
operations and rollback, isolated validation, battle-entry authoring, conditional
music, persisted record order, and list navigation. Production-project checks and
Engine parity checks are optional; skipped checks are not evidence that a production
game or an untested runtime has been validated. CI coverage does not establish WSLg
or native Windows validation.
